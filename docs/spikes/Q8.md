# Q8: Bryntum Scheduler licence
Owner: Ayush · Date: 2026-11-03

## Answer (one paragraph)

Do not add the Bryntum package or commit trial code until the team has written confirmation that
the hackathon sponsor benefit covers this project, every developer who will work on the component,
and the intended hosted demo. Bryntum's published licensing page distinguishes a perpetual
end-user licence from an OEM licence for commercial/SaaS applications and says each developer
with access to the component needs a unique licence. Keep the timeline contract and view isolated
behind a small adapter so the rest of the dashboard can proceed; use a clearly labelled ordinary
HTML event list as a temporary fallback if access is not confirmed by feature freeze.

## Evidence

- Bryntum licensing page, checked 2026-11-03: <https://bryntum.com/licensing/>. It describes
  end-user and OEM licences, says commercial/SaaS applications require an OEM licence, and requires
  a unique licence for each developer working with the code/components.
- Scheduler docs, checked 2026-11-03: <https://bryntum.com/products/scheduler/docs/guide/Scheduler/overview>.
  The trial is available through Bryntum's download flow, but the docs do not establish that a trial
  is suitable for a public or production deployment.
- The published pages do not state whether the PayPal AI Hackathon sponsorship grants a team licence.
  Confirm that point with the sponsor/Bryntum in writing before adding a dependency.

## Impact on the design

No Bryntum licence key or trial distribution files belong in this repository. The timeline data
contract is independent of the vendor. A vendor-specific adapter should accept the documented
`resources[]` and `events[]` shape and must keep simulated events visually distinct. No architecture
change is made pending written licence confirmation.
