# Q7: Does PayPal JS SDK v6 subscribe work, including in a popup?
Owner: Om (issue #31) · Date: 2026-11-12 · **Answered: yes, v6 works on the sandbox, with one wrinkle (the popup relaunch screen)**

## Answer
**The v6 subscribe flow works end to end.** On a plain local page (`http://127.0.0.1`, sandbox client id, nothing from Keepwell): `paypal.createInstance({clientId, components: ["paypal-subscriptions"], pageType: "checkout"})` loaded, `findEligibleMethods({paymentFlow: "RECURRING_PAYMENT", currencyCode: "USD"})` reported PayPal eligible, the `<paypal-button type="subscribe">` rendered, a click created the subscription on the server, and `session.start({presentationMode: "auto"}, promise)` opened PayPal's window. The buyer approved there, `onApprove({subscriptionId})` fired in the page, and a server-side read showed **ACTIVE** with a first payment of 1.0.

What matters for us:
1. **v6 creates nothing in the browser.** The click handler calls our server, which creates the subscription with the Subscriptions API and returns `{subscriptionId}`. Pass the *promise* to `session.start` without awaiting it, or the browser may block the popup. This matches `apps/demo-store`'s design (the server creates the subscription before issuing the shopper token).
2. **Popup.** `presentationMode: "auto"` opened a separate PayPal window. In an automated browser the window did not open by itself and the page showed PayPal's overlay: "Don't see the secure PayPal browser? … Click to Continue". Pressing it relaunched the window (it needs a real user click). A person in a normal tab sees the popup directly. Judge Mode should not rely on automation to click through.
3. **Confirm on the server.** `onApprove` hands over `subscriptionId` only. Read the subscription (`status` ACTIVE) before fulfilling, as the demo store already does.
4. **Webhooks follow, a minute later.** For the new subscription: `BILLING.SUBSCRIPTION.CREATED` right away, then `BILLING.SUBSCRIPTION.ACTIVATED` and `PAYMENT.SALE.COMPLETED` about 60 seconds after approval (`fixtures/spikes/q7/95-q7-events.json`).

## What `apps/demo-store` uses
It loads `https://www.paypal.com/sdk/js` (the older script with `Buttons`). PayPal still documents it for existing integrations and recommends v6 for new ones. We did not switch the store (feature freeze) and did not test the older path in this spike. If a judge's browser blocks that popup, the v6 page used here is a working alternative.

## Evidence
The page and local server were a throwaway script (not committed): it serves the client id (public) and creates and reads subscriptions with the app's credentials. Fixtures in `packages/paypal-mock/fixtures/spikes/q7/`: `92-q7-create-sub.json` (server-side create, from the button click), `94-q7-final.json` (ACTIVE, next billing 2026-11-13T10:00Z, last payment 1.0), `95-q7-events.json` (webhook events).
